Click once. See what's using your Mac, why, and what you can safely do.

HeatLens is a free menu-bar app for Apple Silicon Macs. It takes a short sample when you ask, ties busy processes to the projects and tools that started them, separates active work from possible leftovers, and never stops anything without asking you first.

macOS 14 or later · Apple Silicon · free · signed and notarized

How it works

HeatLens lives in the menu bar, has no Dock icon, and does nothing until you ask. One scan is a short, bounded sample; there is no background monitoring and no history.

  1. Click the thermometer

    The popover opens at once. It shows when you last scanned and one button. Until you press it, nothing is being measured.

  2. Scan for ten seconds

    HeatLens measures how much CPU each process actually used over the sample, as the change between two readings, not the lifetime total. You can pick 5, 10 or 15 seconds in Settings, and cancel at any time.

  3. Read what it found

    A one-line status first: High load observed, Thermal pressure reported, Memory pressure, or No significant issue observed. Then ranked findings, each with its evidence, a confidence level, what it cannot prove, and the safe actions.

What it shows

Observation and inference are kept apart. Every number names the sample it came from, and every label says how sure HeatLens is.

Active work, then leftovers

Findings are ranked by measured impact right now. A video export at 80% CPU is listed as active work, not junk. A two-day-old idle worker with parent PID 1 goes under Potential leftovers as a review candidate, never as a verdict, and the card says plainly that stopping it is unlikely to cool your Mac.

Where a process came from

Processes are grouped by their parent tree and the tool that started them: Next.js, Vite, Vitest, Claude Code, OpenCode, generic Node and the rest. The project folder comes from the process's working directory or script path, with a confidence level. When HeatLens cannot tell, it says Unknown project rather than guessing.

Thermal and memory state

The overview reports the thermal state macOS itself publishes (nominal, fair, serious or critical), how many cores were busy, memory pressure and swap. There is no temperature reading and no GPU percentage, because no supported API provides a reliable one. WindowServer activity is shown as UI rendering, not as GPU load.

Ask your AI agent

HeatLens ships a read-only MCP server. Settings → Connect to an AI agent copies the setup command for Claude Code or Codex, and then you can ask your agent "why is my Mac hot?". The agent can run a scan, list ports or see what's keeping the Mac awake, but it can't stop anything, and reports are always redacted.

Mode Read-only, redacted

From the terminal

The same read-only tool works in a terminal. It ships inside the app at HeatLens.app/Contents/Helpers/heatlens; run a scan or list ports and get the same redacted report as text or JSON.

heatlens scan --seconds 5
heatlens ports --json
heatlens awake

What's keeping it awake

When your Mac won't sleep or the display stays on, the results show which process is holding it awake, in which project, and since when: a caffeinate left by a script, a download, a video call. Media and downloads keep a Mac awake on purpose, so this is listed as information, not as a fault.

A heads-up when it runs hot

Optional and off by default. Turn it on in Settings and, when macOS reports serious thermal pressure, HeatLens runs one scan and sends one notification naming the likely culprit, at most every 30 minutes. It listens for macOS's own thermal event, so nothing runs in between. You can also turn on ⌃⌥H to open HeatLens from anywhere.

Your Mac is running hot
next dev in portfolio-demo · 182% CPU

Clear a project's leftovers

When one project has left several dev servers or workers behind, one confirmation lists them all with a checkbox each. HeatLens stops the ones you keep ticked one at a time, checking each is still the same process right before it signals it. Scan again and Since last scan shows what changed and what's gone. Nothing is stored after you quit.

Safe by construction

HeatLens reads. The one thing it can change on your Mac is to send a single, polite stop signal to a process you own, and only after you have read the confirmation and clicked.

  • Fully offline

    No network access, no account, no telemetry, no analytics, no crash reports. The only thing stored is your settings, and no scan history is kept.

  • Read-only diagnosis

    HeatLens looks at the process table and system counters that macOS exposes to any app. It never opens your files, terminal history, environment variables or agent transcripts, and it asks for no permissions: no Full Disk Access, no Accessibility, no Screen Recording, no admin password.

  • A stop is one SIGTERM, confirmed

    Request stop opens a sheet with the PID, command, project and measured impact, and a warning about what might be interrupted. Only then is one SIGTERM sent to that one PID, after re-checking that the PID still belongs to the same process. There is no force-quit, no bulk kill, and HeatLens tells you what happened.

  • Protected processes never get a stop control

    kernel_task, WindowServer, launchd, loginwindow, Finder, the Dock, Spotlight, anything owned by root or another user, and any Apple system binary are shown without a Request stop button. HeatLens only stops processes you own.

Cancel is the default button. If the process ignores the signal, HeatLens reports that it is still running and leaves it alone.

What it can't tell you

These are limits of what macOS exposes without special privileges. HeatLens shows Not accessible or Unavailable in those places instead of estimating.

  • No temperature

    No supported API provides a reliable per-chip temperature. The thermal state is the OS's coarse state, not a measurement of how hot the Mac is.

  • No GPU percentage

    WindowServer CPU is shown as UI and rendering activity. It is a signal, not a GPU figure and not proof of overheating.

  • Other users' processes

    Only your own processes give full details. For root and other-user processes the command line, working directory, memory footprint and precise CPU are not available; CPU comes from ps at 10 ms resolution.

  • kernel_task has no numbers

    It reports no CPU or memory figures to HeatLens, only its name and owner. Its load counts only in the host total.

  • Flags are not proof

    "Possible leftover" means review candidate. A process with parent PID 1 that has run for two days may be an intentional daemon doing useful work, and HeatLens says so on the card.

The full list, with the reasons, is in docs/LIMITATIONS.md.

Questions

Will macOS let me open it?

Yes. Each release is signed with an Apple Developer ID and notarized by Apple, and the notarization ticket is stapled to the disk image, so Gatekeeper opens it without an "unidentified developer" warning. Open the DMG, drag HeatLens to Applications, and launch it. If you want to check for yourself before opening:

spctl -a -t open --context context:primary-signature -vv HeatLens.dmg
Why doesn't it ask for any permissions?

Because it only reads what macOS already lets any app read about running processes: process IDs, parents, start times, executables, CPU and memory counters, and for your own processes the command line and working directory. That is enough to explain most heat and pressure. It does not request Full Disk Access, Accessibility, Screen Recording or an admin password, and it would not learn anything useful from them.

The one exception is optional: if you turn on the thermal alert, macOS asks once whether HeatLens may show notifications.

The flip side is what it can't see: details of root and other users' processes, kernel_task's numbers, the chip temperature, and GPU load. Those places show Not accessible or Unavailable.

Does it run in the background?

Only the menu-bar icon. HeatLens has no timers and no polling; it scans when you click Scan now, or once when macOS reports serious heat if you turned on the optional thermal alert. Measured on the development Mac, the idle app sits at 0.0% CPU with no change in CPU time between samples, and about 18 MB of memory as reported by top. A scan costs about one second of CPU spread over its five to ten seconds. Launch at login is off by default.

Does connecting an AI agent send my data anywhere?

HeatLens itself still makes no network connections; the MCP server runs on your Mac over standard input and output. But whatever the agent receives, it sends to its own model provider, as with anything else you show it. That's why the reports it gets are redacted: personal paths are replaced, and specific network addresses are left out. You choose whether to connect one, and you can remove it with claude mcp remove heatlens.

What exactly happens when I click Request stop?

A sheet shows the PID, command, project and measured impact, and warns that stopping a dev server or agent can interrupt tests, edits, builds or active sessions. Cancel is the default. If you click Send SIGTERM, HeatLens re-reads the process from the kernel, checks that the PID still has the same start time and still belongs to you, and sends one SIGTERM. It waits a few seconds and tells you whether the process exited, is still running, had already exited, or had been replaced by another process, in which case nothing is sent. It never escalates to SIGKILL; for that, it points you to Activity Monitor. When one project has several leftovers, Stop leftovers lists them in one sheet with a checkbox each, and each selected process goes through the same check and single SIGTERM, one at a time.

Why isn't it sandboxed or on the App Store?

A sandboxed build sees much less: it cannot list all processes, read physical memory footprints, or fall back to ps for system processes. That would make the diagnosis mostly guesswork, so HeatLens ships as a notarized direct download instead. It still runs under the hardened runtime, and the source is on GitHub if you'd rather build it yourself.

How do I uninstall it?

Quit HeatLens from the popover, then drag it from Applications to the Trash. If you had turned on Launch at login, turn it off first in the app's Settings, or remove it under System Settings, General, Login Items. The only other thing it leaves behind is its settings file:

~/Library/Preferences/dev.heatlens.HeatLens.plist

Delete that too and nothing remains.

Does it work on Intel Macs?

Not yet. HeatLens targets macOS 14 or later on Apple Silicon, which is where it has been measured and tested.
