## Context
v2 facts (true, use these; don't invent features). Everything new is **off by default**, so
out of the box HeatLens still does nothing until you click, stores nothing but settings, and stops
only with SIGTERM after a confirmation:
- **Live mode** (panel open, every 2/5/10 s): projects (which repository a process belongs to),
  a timeline with expensive commands (installs, builds, test runs) and container starts, and
  plain-language explanations like "2 test runs began within 10 s across 2 agent trees (claude,
  codex)". Explanations are advice only.
- **Keep watching in the background** (off): after the panel closes, samples every 30 s on power /
  60 s on battery, 5–10 s while something is busy, 120 s in Low Power Mode; Quit stops it.
  Measured idle cost is a fraction of a percent of one core (Jarvis fills in the exact number later;
  write "a fraction of a percent of one core").
- **Alerts** (off): CPU, memory, swap, thermal, containers, and per-project watches ("Watch this
  project…" with preset limits); normal notifications that respect Focus.
- **Keep history** (off): a local, owner-only SQLite file, 1/7/30 days, Delete history in Settings.
  Never command lines or file contents.
- **Safe actions**: default is still SIGTERM only, after a confirmation. Two off-by-default
  switches: "Offer Force Quit when a process ignores a stop request" (SIGKILL, behind a second
  confirmation) and "Allow stopping a container" (exactly `docker stop`, one container, from scan
  results only, Docker Desktop's socket only). Live mode never stops anything.
- **Action log**: the stops you confirm are listed in Settings → Recent actions (memory only unless
  Keep history is on). "Ignore this process/project".
- **Incident export**: a redacted Markdown/JSON report saved only where you choose; drops PIDs,
  paths, command lines, container IDs; optional "Project A, B…".
- **Logs**: short operational notes to the macOS unified log, names hidden; no log file of its own.
- Still true: fully local, no account, no telemetry; the only network request is the click-only
  update check; the CLI and MCP server are read-only; hardware sensors read-only.
