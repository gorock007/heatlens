## Goal
User ruling (2026-10-27): the comparison lives **in memory only**. HeatLens stores no scan history (`SettingsModel` doc comment, FR-10), and a relaunch forgets it. Done means:
1. **Core comparison (pure, tested).** Add `Sources/HeatLensCore/Rules/ScanComparison.swift` with `compare(before: ScanResult, after: ScanResult) -> ScanComparison`:
   - host CPU as busy cores (`SystemSample.busyCores`), before → after
   - memory used, before → after (use the same "used" figure the Overview section shows; don't invent a new one)
   - swap used (`swapUsedBytes`), before → after
   - thermal state, before → after
   - **processes gone**: groups in `before` whose root identity (PID **and** start time) is absent from `after`. Give the label, project folder name and the CPU it had, sorted by CPU, at most 5 plus a count of the rest.
   - elapsed time between the two scans
   - Changes below a noise floor are treated as "about the same": under 0.2 cores, under 100 MB, and no change in thermal state.
2. **ScanModel.** Keep the previous results report: when a scan finishes with results and the model already held one, the old one becomes `previousReport`. `dismiss()`/`cancel()` don't clear it. Also track `stoppedSinceLastScan: Bool`, set when a stop or batch stop reports at least one `.stopped`, and cleared when the next scan finishes.
3. **UI: "Since last scan".** In `App/ResultsView.swift`, whenever `previousReport` exists, show a compact section at the top of the results, before the findings: "Since last scan (4 min ago)".
   - One line per metric that changed beyond the noise floor, e.g. "CPU 6.1 → 1.4 cores", "Swap 2.1 GB → 1.3 GB", "Thermal serious → fair".
   - "Gone: next dev (my-app), node watch-images.js (portfolio-demo)".
   - If nothing changed: "About the same as the last scan."
   - Follow the layout of the existing `ResultSection`/`OverviewSection` rows.
4. **After a stop.** In `StopFlowView` (`App/ResultsView.swift`) and `App/BatchStopFlowView.swift`, when at least one process was stopped, the post-stop "Scan again" button reads **"Rescan to see the difference"** and keeps the same action (`onScanAgain`). Report the stop to the model through the smallest closure you can add.
5. **Cleanup from 10a.** Point `ResultsView`'s private `visibleFindings`/`matchesExclusion` at the core `ExclusionFilter` (`settings.exclusions`, added in 10a), so that logic lives in one place. Existing behaviour must not change; the existing tests plus `ExclusionFilterTests` cover it.
6. **Fixtures.** Add a previous report to the `ResultsView` preview, so the section renders: the fixture report with one group removed and lower CPU.
