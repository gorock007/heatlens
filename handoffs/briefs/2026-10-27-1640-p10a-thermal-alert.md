## Goal
User ruling (2026-10-27): **opt-in, off by default.** When the setting is on and macOS's thermal state rises to `serious` or `critical`, HeatLens runs **one** normal scan and posts a notification naming the top culprit. Clicking the notification opens the panel on those results. **At most one alert per 30 minutes.** No polling, no timers, no background sampling: the only trigger is `ProcessInfo.thermalStateDidChangeNotification` (PRD §2 non-goal "always-on monitoring"; §7 "optional opt-in notifications, off by default"; FR-10 no telemetry). Done means:
1. **Core policy (testable).** New `Sources/HeatLensCore/Rules/ThermalAlertPolicy.swift`, a pure value type:
   - `shouldScan(previous: ThermalState, current: ThermalState, enabled: Bool, lastAlert: Date?, now: Date, scanRunning: Bool) -> Bool`. True only on a rise **into** serious/critical (fair→serious, nominal→critical, serious→critical counts, critical→serious doesn't), enabled, no scan running, and 30 min since `lastAlert`. Use the core `ThermalState` from `Sources/HeatLensCore/Model/SystemSample.swift`.
   - `summary(for report: ScanReport) -> (title: String, body: String)`. Title "Your Mac is running hot". Body names the top-ranked visible finding's group: label, project when known, CPU, e.g. `next dev in my-app · 182% CPU`. With no CPU finding: "No single process stands out. macOS reports serious thermal pressure." Keep it under ~110 characters. **Never put argv, paths beyond the project folder name, or usernames in the notification.**
2. **App service.** New `App/ThermalAlertService.swift` (`@MainActor`). It observes the notification only while the setting is on, asks the policy, calls `ScanModel.startScan()`, and posts the notification with `UserNotifications` when that scan finishes with results. Failed or cancelled scans post nothing. Clicking (UNUserNotificationCenterDelegate) opens the panel showing the results already in the model.
3. **ScanModel hook.** Give `App/ScanModel.swift` the smallest way to learn when a given scan finished, e.g. an `onFinish` closure or an async `runScan() -> ScanReport?`. Existing behaviour and the generation/cancel logic stay unchanged.
4. **StatusPanel.** Expose a public `show()` on `StatusPanelController` (today `open()` is private), and nothing else.
5. **Settings.**
   - `SettingsModel.thermalAlertsEnabled`, stored in UserDefaults, default `false`.
   - A toggle in `App/SettingsView.swift`: "Alert me when my Mac runs hot", with the caption "Runs one scan when macOS reports serious thermal pressure, at most every 30 minutes. Nothing runs in between."
   - Turning it on requests notification authorization. If it's denied, show "Notifications are off for HeatLens" with a button that opens System Settings › Notifications.
6. **Wiring.** Create the service in `AppDelegate` (`App/HeatLensApp.swift`) next to the model.
7. **Debug trigger.** Add a `#if DEBUG`-only launch argument `-HeatLensSimulateThermal serious` that feeds one synthetic rise into the service 3 s after launch, so it can be checked without heating the Mac. It must not exist in Release.
8. **Docs.** Add one README feature line. Add a short note to `docs/PERFORMANCE.md` that idle cost doesn't change (one notification observer, no timer).
