## Goal
PRD-v2 Phase 3: "Record a local audit trail of suggested and executed actions." Every stop, force quit and container stop already produces an `ActionRecord` in the session's one `StopLedger` (`Sources/HeatLensCore/Safety/StopLedger.swift`; record shape in `docs/v2/ADR-0006-force-quit.md` §Audit record).

User ruling (2026-10-28): **the log lives in memory; it is saved to disk only while "Keep history" is on.**

**Done when** `swift build`, the filtered and the full `swift test`, and `scripts/run-app.sh --build-only` pass, and:
1. **Core: two new action kinds.** `ActionRecord.Action` gains:
   - `.ignored`: the user chose "ignore this process/project", for 3e-2
   - `.cancelled`: a stop, force quit or container stop was offered and the user backed out at its confirmation. That's the "suggested" half of the audit trail.

   Add any `Target` case needed for an ignored *project*, e.g. `.project(name)`, names only. `Origin` gains what 3e-2 will need (`findingCard`, `projectRow`). Keep `Codable` stable; old records still decode. Update the §Audit record table in ADR-0006 (`docs/v2/ADR-0006-force-quit.md`) to match.
2. **Core: in-memory lifetime.** The ledger keeps the whole app session's records, up to 500 newest, instead of pruning at 10 minutes. The force-quit lookup (`stopRequestedAt`) must still apply its own 60 s rule; don't loosen it. Add `records()` (newest first) if the API lacks it.
3. **Core: persistence.** `HistoryStore` gains an `actions` table, created with `CREATE TABLE IF NOT EXISTS` so existing databases upgrade in place, plus `record(actions:)` and `actions(since:)`.
   - Store the record's fields as columns, or as one bound JSON text column plus `ts`, `action` and `outcome` columns. Your call; say which in the handoff.
   - Retention and the row caps apply (cap 5,000).
   - **Delete history** removes them along with everything else.
   - Everything bound with `sqlite3_bind_*`, as the rest of the file does.
   - Never argv or paths: the record type already enforces this; keep it.
4. **App: who writes.** When a record is added to the ledger *and* `settings.keepHistory` is on, it's also written to the history store (through `App/HistoryService.swift`). Records made while Keep history was off are **never** written later. Turning Keep history on starts saving from that moment only. Put the hook where it fits best, e.g. a small observer the ledger calls or a wrapper in `App/StopService.swift`, and keep `Sources/HeatLensCore/Safety/ProcessTerminator.swift` untouched.
5. **App: "Recent actions" in Settings.** A section near the history section (`App/SettingsView.swift`, `HistorySection` ~line 146), in a new file `App/ActionLogSection.swift`:
   - a collapsed disclosure "Recent actions (N)" listing the newest 50, one line each, e.g. `14:02 · Stop requested · node (my-app) · stopped`, `14:03 · Force quit · node (my-app) · refused: Force Quit is off in Settings`, `15:10 · Container stop · fda-db-1 (FDA) · stopped`
   - from memory, plus the saved ones from the history store when Keep history is on, de-duplicated by `id`
   - a caption: "Kept until HeatLens quits." or "Also saved with your history for N days.", depending on Keep history
   - no actions in this list: it's read-only
6. **ADR-0005 addendum.** Add a short "Addendum (3e)" section to `docs/v2/ADR-0005-history-store.md`: the app now writes `actions` rows outside Live, only while Keep history is on; what's stored; and that Delete history removes them.
7. **Tests:**
   - `HistoryStoreTests`: an actions round trip; an old-schema database (create one without `actions`) opens and gains the table; retention and Delete history drop actions; a bound injection string survives.
   - `StopLedger` tests (add to `ForceQuitTests.swift` or a new `StopLedgerTests.swift`): 500 cap; records older than 10 min are kept, but `stopRequestedAt` still refuses past 60 s; new kinds encode/decode; an old JSON record without new fields decodes.
