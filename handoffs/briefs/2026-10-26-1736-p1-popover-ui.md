## What to build (all in `App/`)
- `project.yml`: link the local package (`packages: HeatLensCore: path: .`) and add the `HeatLensCore` product as the app target's dependency. If xcodegen or Xcode objects to the package root containing the project, say so in the handoff and keep the smallest working layout. Don't move `Package.swift`.
- `ScanService.swift`:
  - `protocol ScanService: Sendable { func run(duration: TimeInterval, progress: @escaping @Sendable (TimeInterval) -> Void) async throws -> ScanReport }`
  - `struct ScanReport { snapshot: ScanSnapshot; groups: [ProcessGroup]; findings: [DiagnosticFinding]; reportText: String }`. The findings array order is the ranking; keep it.
  - `FixtureScanService`: ticks once a second with `Task.sleep` (cancellable), then returns a synthetic report modelled on PRD §7. That means an opencode group at 44% (active work), a detached `node …/scripts/worker.js` at 2d 5h and 0% (review), a `next dev` at 38 h (review), thermal `unavailable`, memory pressure normal with swap 8.5 of 10 GB, and two notices. Use invented paths like `~/Projects/demo-site` only.
- `ScanModel.swift`: `@MainActor @Observable`, with state `idle(lastScan: Date?) | scanning(elapsed:total:) | results(ScanReport) | failed(String)`, plus `startScan(duration:)` and `cancel()`. Only one scan at a time. Cancelling returns to idle with the previous lastScan. No timers except inside a running scan.
- Views:
  - **Idle:** the existing view plus a real "Last scan: <relative time>".
  - **Scanning:** "Measuring process activity (7 of 10 seconds)", a progress bar, and **Cancel**.
  - **Results** (in a `ScrollView`, popover max height ~560 pt):
    - **Headline**, derived in the app: thermal `serious`/`critical` → "Thermal pressure reported"; memory pressure warning/critical → "Memory pressure"; host busy ≥ 60% or any `high`/`medium` CPU finding → "High load observed"; otherwise "No significant issue observed". Never claim a cause. Add "· 10-second sample".
    - **Overview:** thermal ("Unavailable" when so), CPU load as "3.2 of 11 cores busy", memory pressure, swap, and the notices.
    - **Findings:** non-`review` severities in array order.
    - **Potential leftovers:** `review` findings.
    - **What's using resources:** groups in `DisclosureGroup`s with member CPU, memory and uptime.
    - **[Copy report]** copies `reportText`; **[Scan again]**.
  - **Finding card** (PRD §3 example): title, severity and confidence chips, explanation, an expandable "Evidence" list, limitations, and action buttons for `copyCommand` (pasteboard), `openProject` (NSWorkspace, folder), `openActivityMonitor` and `copyReport`. **Never render `requestStop`** (Phase 2). `inspect` can expand the card.
  - **CPU format:** "44% CPU (of one core)"; above 100%: "180% CPU (≈1.8 cores)". Show "Not accessible" for nil argv, cwd or CPU. Never fabricate a temperature.
- Settings (sample duration and so on) are out of scope. Default the duration to 10 s.
