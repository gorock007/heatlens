## What changed
- **`StopLedger`** (actor, new file) records every stop/force-quit attempt, sent or refused,
  in memory for the app session. Entries older than 10 min are dropped.
  `stopRequestedAt(identity)` returns the newest `stopRequested` entry for exactly that
  pid + start time *whose signal was actually sent*. `records(since:)` returns them oldest first.
- **`ActionRecord`** has the §Audit record fields (`id, at, action, target, projectName, origin,
  confirmedAt, signalSentAt, outcome, detail`). It is `Codable` so 3e can persist it as is. Its
  init enforces the caps: names, images and the project name ≤ 80, container short ID 12,
  `detail` ≤ 200 and redacted. `outcome` is the `StopOutcome` case name (`StopOutcome.caseName`).
- **`ProcessTerminator`**: the v1 sequence (identity → live uid + `eligibility` → last identity
  read → one `kill` → poll) now lives in one private `signalOnce(_ signal:…)`, so both entry
  points run exactly the same checks.
  - `requestStop(_:wait:ledger:context:)` calls `signalOnce(SIGTERM…)` and records the attempt.
    `signalSentAt` is taken right after `kill` returns 0 and is nil when the stop was refused.
  - `forceQuit(_:ledger:wait: = 2, context:)` goes through these steps in order:
    - refuses pid ≤ 1;
    - refuses when the ledger has no sent SIGTERM for that identity;
    - refuses when that SIGTERM is more than 60 s old;
    - waits out the rest of the 5 s grace, and a cancel during that wait refuses with nothing sent;
    - calls `signalOnce(SIGKILL…)`. That is the only `SIGKILL` in `Sources/`.

    The attempt is always recorded. Constants: `minimumGraceAfterStop = 5`, `offerLifetime = 60`
    (public, so 3d-2 can show the countdown from the same numbers).
  - Doc comments updated: `StopOutcome.stopped` and `.stillRunning` now cover both signals.
    The type comment states the new invariant without the literal `SIGKILL`/`killpg` tokens, so
    the done-condition greps stay at one line and zero lines.
- `requestStop`'s existing callers (`App/StopService.swift`, the tests) compile unchanged,
  because the new parameters have defaults.

## Notes for Jarvis
- **Two choices I made beyond the ADR's wording** (additive; tell the 3d-2 builder):
  1. **`ActionContext`.** The engine can't know `origin`, `projectName` or `confirmedAt`, so
     both entry points take an optional last parameter
     `context: ActionContext? = nil` (`origin`, `processName`, `projectName`, `confirmedAt`).
     Without it, `origin` and `confirmedAt` are nil in the record; they are optional for that
     reason. The record's process name is the kernel's `pbi_name` when HeatLens read it, else
     `context.processName`. **3d-2 should pass a context from `StopFlowView`/`BatchStopFlowView`**
     (origins `processDetail`, `leftoverCard`, `batchStop`) so 3e's audit trail is complete.
  2. **Redaction of `detail`.** ADR says "passed through `Redactor.text`", but that doesn't exist
     as an entry point: the `Sanitizer` is `private` in `Redactor.swift`, which was outside my
     scope. `ActionRecord.redacted` repeats the relevant rules: home → `~`, the user name →
     `<user>`, secret flags and assignments. The details are HeatLens's own reason strings, so
     no argv ever enters. 3e (or a small follow-up) can add `Redactor.text(_:)` and switch to it.
- The ADR's suggested doc-comment wording "SIGKILL only from forceQuit" would add a second
  `SIGKILL` line and break the brief's own grep condition. I used "the uncatchable kill signal"
  instead.
- `StopLedger` records the `requestStop` attempt after its poll ends. A `forceQuit` issued
  *during* that 3 s wait therefore finds no entry and is refused, which is the safer side.
- Suggested commit message:
  `feat(v2): Phase 3d-1 — StopLedger and ProcessTerminator.forceQuit (ledger-gated, 5 s grace, 60 s expiry, one SIGKILL site)`
