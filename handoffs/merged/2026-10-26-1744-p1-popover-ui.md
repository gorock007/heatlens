## What the user asked
The menu-bar popover runs the whole PRD §3 flow (idle → cancellable progress → results with overview, findings, leftovers and groups) against a fixture `ScanService`, linking `HeatLensCore` and rendering its real model types, so the wiring brief only swaps the service.
## What changed
- `project.yml` links the local package (`packages: HeatLensCore: path: .`) and gives the app target a `HeatLensCore` product dependency. xcodegen and Xcode raised no objection to the package root also holding the project, so no layout change was needed.
- `ScanService` protocol and `ScanReport` struct, matching the brief's signatures exactly. `FixtureScanService` ticks once a second with a cancellable `Task.sleep`, then returns a synthetic PRD §7 report:
  - OpenCode group at 44% across 2 processes (medium finding, ranked first)
  - detached `node …/scripts/worker.js`: PPID 1, 2d 5h, 0% (review)
  - `npm run dev → next dev → next-server` at 38h (review)
  - a Safari group at 12.5% and a WindowServer group with nil CPU, memory, argv and cwd, which shows "Not accessible"
  - an info finding for swap
  - thermal `unavailable`, memory pressure normal, swap 8.5 of 10 GB, two notices
  - Paths are invented `~/Projects/*-demo` paths only.
- `ScanModel` (`@MainActor @Observable`) has the states `idle(lastScan:) | scanning(elapsed:total:) | results | failed`, plus `startScan(duration:)` (10 s default), `cancel()` and `dismiss()`.
  - Only one scan runs at a time: a second `startScan` is ignored.
  - Cancel returns to idle with the previous lastScan.
  - A generation counter drops progress or results that arrive late from a cancelled scan.
  - The only timer is the service's sleep inside the scan task.
- Views:
  - **Idle:** "Last scan: never", or a relative time ("just now", "2 minutes ago") inside `TimelineView(.everyMinute)`, which only exists after a first scan.
  - **Scanning:** "Measuring process activity (N of 10 seconds)", a progress bar and Cancel (Esc).
  - **Results:**
    - The headline is derived in the app, plus "HeatLens · 10-second sample".
    - Below it is a 440 pt `ScrollView` (about 560 pt total popover) holding Overview, Findings (non-review severities, in array order), Potential leftovers (review findings) and What's using resources (`DisclosureGroup` per group, with member CPU, memory and uptime).
    - Footer buttons: Done (back to idle), Copy report, Scan again.
  - **Finding card:**
    - Content: title, severity and confidence chips, explanation, an expandable Evidence list (label: value, plus the source), and limitations.
    - Action buttons, wrapped with a small `FlowLayout`:
      - Inspect: expands the FR-04 process details (PID, parent, uptime, executable, command, directory, CPU, memory, each "Not accessible" when nil).
      - Open project: `NSWorkspace`, disabled with a tooltip when the folder doesn't exist.
      - Copy command: argv shell-joined to the pasteboard, disabled when argv is nil.
      - Activity Monitor.
      - Copy report.
    - `requestStop` is filtered out and never rendered. The fixture includes it on 3 findings to prove that.
  - **CPU format:** "44% CPU (of one core)", or above 100 "180% CPU (≈1.8 cores)". Values under 10 show one decimal. No temperature is shown anywhere.
- `HeatLensApp` owns the `ScanModel` and passes it to `PopoverView`.
