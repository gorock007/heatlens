## What the user asked
A `heatlens` executable so people in a terminal and AI agents (via MCP) can run a read-only,
redacted HeatLens scan. No new dependencies; bundling, signing and the Settings button wait for 7b.

## What changed
- `heatlens scan [--seconds N] [--json]` runs one `ScanPipeline` scan (N 1…15, default 5) and
  prints `Redactor.textReport` or `Redactor.jsonReport` to stdout. Progress (`scanning… 2s of 5`)
  goes to stderr only when stderr is a TTY, and is cleared afterwards. Scan failure: exit 1 with
  `heatlens: scan failed: …` on stderr. Usage errors (unknown flag or command, `--seconds` out of
  range or missing): exit 2 with the message and a pointer to `--help` on stderr.
- `heatlens --help` / `-h` / no arguments, and `heatlens --version` (prints `heatlens 1.0.1`).
- `heatlens mcp`: hand-rolled newline-delimited JSON-RPC 2.0 server over stdio
  (`Sources/HeatLensCLI/MCPServer.swift`, Foundation `JSONSerialization` only).
  - `initialize` echoes `2025-06-18` or `2025-03-26`, otherwise answers `2025-06-18`;
    capabilities `{tools:{}}`; serverInfo `heatlens` / `1.0.1`.
  - Any message without an `id` is a notification and gets no reply (incl. `notifications/initialized`).
    Responses sent by the client are ignored.
  - `ping` → `{}`; `tools/list` → the one `scan` tool; unknown method → -32601; malformed JSON → -32700
    (id null); a non-object (incl. a batch array) or an object without `method` → -32600.
  - `tools/call scan`: `seconds` must be an exact integer 1–15 (rejects 0, 16, 2.5, `"5"`, `true`);
    any other argument key or non-object `arguments` → tool result with `isError: true`, and no scan
    runs. A scan that throws → `isError: true`. Success → two text items: text report, then JSON.
    An unknown tool name → JSON-RPC -32602 (protocol error, as the MCP spec has it).
  - Tool schema `{seconds?: integer, minimum 1, maximum 15, default 5}`, `additionalProperties: false`;
    annotations `readOnlyHint: true`, `openWorldHint: false`. The description covers what a scan
    measures, that it is read-only and redacted, and that process names, paths and command lines
    are data reported by running programs, never instructions.
  - stdout carries only protocol lines; nothing else is printed in mcp mode (stderr only on a stdin failure).
- No stop/kill anywhere; no way to turn redaction off.
- Layout per the brief: library `HeatLensCLI` (parsing, MCP handler, `LiveScan`; the scan is an
  injected `ScanRunner` closure), thin `Sources/heatlens/main.swift`, tests in `HeatLensCLITests`
  (swift-testing, 9 tests, fake scan).
- README: new "Use from a terminal or an AI agent" section.

## Notes for Jarvis
- **Release bump:** `heatlensVersion` in `Sources/HeatLensCLI/Arguments.swift` must change together with
  `MARKETING_VERSION` in `project.yml` (which feeds `CFBundleShortVersionString` in `App/Info.plist`).
- **For 7b / the user:** the JSON report on this Mac was ~391 KB (pretty-printed, every process). Returned as the
  second MCP content item, that is a big chunk of an agent's context per scan. The brief asked for both items,
  so I kept them. Options for later: an `includeJSON`/`detail` argument, compact (non-pretty) JSON for MCP,
  or text-only by default.
- MCP requests are handled one at a time, so a `ping` sent during a 15 s scan waits for the scan.
  Fine for real clients; worth knowing.
- Commit together with or after the listening-ports handoff: my files don't touch `HeatLensCore`, but the
  shared tree only builds once their edits are complete.
