## What the user asked
PRD-v2 Phase 3's local audit trail, following the 2026-10-28 ruling: the log lives in memory
and is saved to disk only while "Keep history" is on. The records already existed (every stop,
force quit and container stop goes into the session's one `StopLedger`). This brief keeps them
for the whole session, saves them while Keep history is on, and lists them in Settings. It also
adds the types 3e-2 needs. No questions were needed.
## What changed
- **`ActionRecord`** (`StopLedger.swift`):
  - New actions `.ignored` and `.cancelled`.
  - New target `.project(name:)`, capped at 80 like other names.
  - New origins `findingCard` and `projectRow`.
  - New optional field `offered: Action?`, for `.cancelled`: which action the user backed out of.
    It defaults to nil in `init`, so existing callers are unchanged.
  - Synthesized `Codable` uses `decodeIfPresent` for optionals, so an old record without
    `offered` still decodes (tested with literal pre-3e JSON).
  - Doc comment updated.
- **`StopLedger`** keeps the session's newest **500** records (`capacity`); the 10-minute pruning
  is gone.
  - `records()` returns them newest first. `records(since:)` is unchanged (oldest first).
  - `init(onRecord:)` takes an optional observer. The ledger calls it on its own actor as each
    record is added.
  - `stopRequestedAt` still looks back only 10 minutes (`stopLookupWindow`, the old retention).
    The 60 s expiry stays in `ProcessTerminator.forceQuit`. This keeps force-quit behaviour
    exactly as before: 60 s–10 min says "too long since the stop request"; past 10 min says "No
    stop request…".
- **`HistoryStore`** gains a table:
  `actions (id TEXT PRIMARY KEY, ts, action, outcome, record)`.
  - **I chose one JSON column** (`record`, the `ActionRecord` JSON with sorted keys, bound as
    text) plus columns for `id`, `ts`, `action` and `outcome`.
  - It's created with `CREATE TABLE IF NOT EXISTS`, with an index on `ts`, so existing databases
    upgrade in place.
  - `record(actions:)`: one transaction, `INSERT OR IGNORE` by id, so each record is stored once.
    It runs maintenance at most once a minute, like a tick does, so retention applies even
    without Live.
  - `actions(since:limit:)`: newest first. Rows that no longer decode are skipped.
  - Retention deletes old `actions` rows. A cap of `maximumActions = 5_000` is checked hourly
    with the other caps.
  - Delete history unlinks the whole file, so actions go with everything else.
  - Every value goes through the existing `sqlite3_bind_*` path.
- **App: who writes** (`App/HistoryService.swift`, new `@MainActor @Observable final class
  ActionLog`):
  - `ActionLog.shared` owns the session's one `StopLedger`. `AppDelegate` now takes
    `ActionLog.shared.ledger` instead of creating its own, and calls `follow(settings)`.
  - **The save decision is made as the record is added.** The ledger's `onRecord` reads a
    lock-protected mirror of Keep history, then yields `(record, save)` into an `AsyncStream`.
  - The mirror follows `settings.keepHistory` via `withObservationTracking`.
  - On the main actor, a record is written only if it was flagged `save` **and** Keep history
    is still on. So:
    - a record made while Keep history was off is never written;
    - turning it on saves from that moment;
    - a record made just as it was turned off isn't written either.
  - A write opens the store through `HistoryService.store(retentionDays:)`. A write error shows
    in red under Recent actions.
  - `HistoryService.existingStore(retentionDays:)` opens the store only if the file exists, so
    reading saved actions in Settings never creates an empty database.
  - After Delete history, `HistoryService.deleteHistory` bumps `ActionLog.revision`, so the list
    reloads.
  - `ProcessTerminator.swift` is untouched.
- **App: "Recent actions"** (new `App/ActionLogSection.swift`). It's inserted in
  `SettingsView` right after `ActionsSection`, which comes directly after `HistorySection`'s
  group.
  - A collapsed `DisclosureGroup` "Recent actions (N)", where N is the total number of distinct
    records.
  - It lists the newest 50, one line each, for example
    `14:02 · Stop requested · node (my-app) · still running` and
    `Force quit · node (my-app) · refused: Force Quit is off in Settings`.
  - Records from earlier days show as `Oct 27, 14:02`.
  - The source is memory plus, while Keep history is on, the saved rows, de-duplicated by `id`.
  - The caption says "Kept until HeatLens quits." or "Also saved with your history for N
    days." The list is read-only (the text is selectable).
  - It reloads on appear, on expand, on every new record, when Keep history changes, and after
    Delete history.
  - `ActionLogLine` holds the wording, including the 3e kinds: "Cancelled force quit · … ·
    nothing sent", and "Ignored · project my-app".
- **One wording change beyond the brief:** the Keep history caption in `HistorySection` said
  "Only while Live runs", which is no longer the whole story. It now adds: "Also saves the stops,
  force quits and container stops you confirm, with their outcome (see Recent actions)." It's a
  one-sentence text change in `SettingsView.swift`.
- **Docs:**
  - ADR-0006 §Audit record: the intro paragraph and table rows now cover the new actions, the
    project target, the new origins, `offered`, and `confirmedAt`/`outcome` for the new kinds.
  - ADR-0005: "Addendum (3e): action records" covers the second writer outside Live (only while
    Keep history is on), the shape, what's stored, the bounds, Delete history and the Settings
    list.
  - PLAN.md: 3e is marked "Audit trail done (brief 3e-1)", and 3e-2 is named as the rest.

## Verification (the user's click-through)
1. `scripts/run-app.sh`. Settings: below Actions there's **Recent actions (0)** (collapsed) and
   the caption "Kept until HeatLens quits." Expand it: "No actions yet."
2. Keep history **off**. In Terminal, from a project folder:
   `bash -c 'trap "" TERM; exec sleep 600'`.
   - **Scan now** → open that `bash` → Request stop → Send SIGTERM. It ends "still running".
   - Open Settings: **Recent actions (1)** shows
     `HH:MM · Stop requested · bash (<project>) · still running`.
3. With Force Quit off, open the process again and request stop again. With the switch on, try
   Force quit…. Each attempt adds a line. With the switch off, a force quit would read
   `refused: Force Quit is off in Settings`.
4. Turn **Keep history on**. The caption becomes "Also saved with your history for 7 days." The
   records from step 2–3 are still listed (from memory) but **not saved**. Do one more stop on a
   fresh `sleep 600` (end it with Ctrl-C afterwards).
5. Quit HeatLens and relaunch. Recent actions now shows only the stop from step 4: it was saved
   and the earlier ones weren't. To double-check, run
   `sqlite3 ~/Library/Application\ Support/HeatLens/history.sqlite "select ts, action, outcome from actions"`.
   It prints one row (or one per action made after step 4).
6. **Delete history…** → the list drops the saved row (on relaunch, nothing is listed).
7. Turn Keep history off: the caption goes back to "Kept until HeatLens quits."

Only signal the `bash`/`sleep` you started in step 2.
