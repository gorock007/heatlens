## What the user asked
Fix the two Phase 2 click-through failures: Live's Top CPU / Top memory rows should open process
detail (Back returns to Live), and the Settings footer should stop claiming "no history" when
Keep history is on.
## What changed
- **Live → process detail.** Each row in Live's Top CPU and Top memory lists is now a plain
  button (whole row clickable, a trailing chevron, "Inspect process" tooltip — same pattern as the
  Ports/Awake rows in results). Clicking it builds a `ReportContext` from that tick's
  `ScanReport(snapshot:groups:findings: [] …)` and stores it with the identity in LiveView's
  `@State`, so the detail is pinned to the clicked update: later ticks don't change it, and a
  process that exits still shows its data from that update. `ProcessDetailView` replaces the Live
  content; Back clears the selection and shows the newest tick. `LiveModel` is untouched, so Live
  keeps ticking while detail is open.
- **No stop from Live.** `findings` is empty, so `offersStop` is false and Request stop never
  appears. As a second guard, Live passes a private `LiveNoStopService` whose eligibility is
  `.denied` and whose `requestStop` sends nothing (Live has no access to the app's real stop
  service, and I didn't touch `PopoverView.swift` to pass it in).
- **Settings footer** depends on `settings.keepHistory`:
  - off: "Settings are stored on this Mac. HeatLens keeps no history."
  - on: "Settings are stored on this Mac. Live mode keeps history on this Mac for N days; scans
    are never saved." ("1 day" when retention is 1.) It updates as the toggle/picker change.
- **Same claim elsewhere (not edited, Jarvis decides):**
  - `site/index.html:249` — "There is no background monitoring and no history."
  - `site/index.html:432` — "No scan history. Apart from your settings, nothing is stored after
    you quit." (true for scans, but "nothing is stored" is wrong when Keep history is on)
  - `README.md:90` and `docs/LIMITATIONS.md` are already correct (README mentions the opt-in
    local history; LIMITATIONS items 11/21 describe it accurately).
