## What the user asked
Compare a scan with the one before it, in memory only. Show a "Since last scan" section with the CPU, memory, swap and thermal changes and the processes that are gone. After a stop, the "Scan again" button reads "Rescan to see the difference". Rulings (2026-10-27): compare **memory pressure** (any level change counts; the 100 MB floor is for swap only). A gone group counts only if one of its members was named in a previous-scan finding **or** it used at least 0.2 cores. Exclusions still hide.
## What changed
- **Core (`ScanComparison.compare(before:after:exclusions:)`, pure):**
  - It returns before/after values for busy cores, memory pressure, swap used and thermal state, plus the elapsed time from the previous scan's start to this scan's start.
  - A `…Changed` flag per metric applies the noise floor: under 0.2 cores and under 100 MB (`100 << 20`) count as no change. Any change in pressure or thermal level counts.
  - `isAboutTheSame` is true when nothing changed and nothing is gone.
  - **Gone:** a previous group whose root identity (PID **and** start time) isn't among this scan's processes.
    - It qualifies only if one of its members was named in a *visible* (not excluded) finding of the previous scan, or the group used at least 20% of one core.
    - Groups whose root process name or project directory the exclusions hide are skipped.
    - Each gone group gives its label, the project folder name and its CPU (the sum of its members').
    - Highest CPU first, at most 5, plus `moreGoneCount`.
- **ScanModel:**
  - `previousReport` holds the results before the latest ones. A new results report moves the last one there, and Done, a cancel or a failed scan change neither. Memory only, so a relaunch forgets it.
  - `stoppedSinceLastScan` is set by `recordStop()` and cleared when the next scan ends with results. A failed or cancelled scan leaves it set.
- **ResultsView:**
  - When `previousReport` exists, a "Since last scan (4 min ago)" section is first in the scroll view, above Overview. The elapsed time uses `PowerAssertion.durationText`, so it reads "under 1 min" / "4 min" / "1 h 5 min".
  - The section uses the Overview's `ResultSection` + label/value `Grid` layout: one row per changed metric ("CPU 6.1 → 1.4 cores", "Memory pressure Warning → Normal", "Swap 2.1 GB → 1.3 GB", "Thermal Serious → Fair") and a "Gone" row ("next dev (my-app), node watch-images.js (portfolio-demo), and 2 more"). When nothing changed it shows "About the same as the last scan."
  - The comparison uses `settings.exclusions`.
- **After a stop:**
  - `StopFlowView` and `BatchStopFlowView` take an `onStopped` closure. They call it when the single stop returns `.stopped`, or when a batch run finishes with at least one `.stopped`. `BatchStopRun.start` gained an `onFinish(stoppedAny)` callback for this.
  - In both sheets, after at least one process is stopped, the post-stop button reads **"Rescan to see the difference"** and keeps the same `onScanAgain` action.
  - `PopoverView` wires `onStopped` to `model.recordStop()`.
  - **One addition beyond the brief:** the results' own bottom "Scan again" button also reads "Rescan to see the difference" while `stoppedSinceLastScan` is set. This is so the flag the brief asked for is used after the sheet is closed with Done. It's one line in `ResultsView` if you'd rather drop it.
- **10a cleanup:** `ResultsView`'s private `visibleFindings`/`matchesExclusion` are gone. `visibleFindings` now calls `settings.exclusions.visibleFindings(…)`. Same logic: name match ignoring case, the first group containing the identity for the project, and the same prefix rule.
- **Fixtures:**
  - `FixtureScanService.report(startedAt:interval:processClock:afterStop:)`. `processClock` anchors process start times, so two reports see the same identities.
  - `afterStop` drops the image watcher (its process, group and finding) and lowers CPU from 3.2 to 1.4 busy cores.
  - The `ResultsView` preview passes a previous report from 4 minutes earlier, so it shows "CPU 3.2 → 1.4 cores" and "Gone: Node script watch-images.js (portfolio-demo)".
  - `FixtureScanService.run` now uses one process clock per app run. Without it, every fixture rescan in `-HeatLensFixtures` mode would have listed every group as gone.
