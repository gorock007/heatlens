## What changed
1. **Title counts trees per agent.** `ConcurrencyRules.treeNames` counts agent trees per name, most first, then by name, with "no agent" last.
   - 2 claude + 1 codex now reads "across 3 agent trees (claude ×2, codex)".
   - One each still reads "(claude, codex)".
   - "no agent ×2" is handled too, but explanations can't produce it today. Every command with no agent above it shares the one `AgentTree.noAgent` value, so those commands count as a single tree, as they did before. Splitting them would change the burst rule (≥ 2 trees), so I left it alone.
2. **Timeline.** Shows the newest **12** events (was 6). When there are more, a "Show all N events" disclosure lists the rest, newest first, in the same row style. No other layout change.
3. **Alert banner.**
   - **Cause confirmed: the banner lasted one tick.** In a new test, swap held at 3 GB for 10 minutes fires exactly once, on the tick that completes 1 minute, then stays quiet. So the evaluator fires, and the banner was simply up for a single 5 s update.
   - **Tick jitter can't reset the hold, so no bug and `AlertPolicy.swift` is untouched.** `LiveMonitor` starts each tick at the previous reading's wall clock and makes it last the monotonic time between the two readings. So the next tick starts where the last one ended, give or take the microseconds between reading the two clocks. The collection time (100–200 ms) is inside the interval; it doesn't show up as a gap. A new test feeds 10 minutes of ticks shaped that way, 5 s + 100–200 ms with ±5 ms clock skew. CPU fires at about 120 s and swap at about 60 s, once each.
   - **Two other things could have kept Run 2's banner away.** I can't tell from the report which applied.
     - (a) "Alert me while Live is running" is off by default, and the report doesn't say it was on.
     - (b) The evaluator lives in `LiveMonitor` for the whole app run. Once swap fires, it re-arms only after swap drops below 1 GB, and the 15-minute cooldown carries across Start/Pause. So if swap fired during the first pair (13:35, or earlier in that app run) and stayed above 1 GB, the second pair gets nothing. That is the intended hysteresis, but it can look like "no alert". The Timeline would still show the first `.alertFired` event.
   - **Fix (app side).** `LiveModel.recentAlerts` keeps the most recent tick's alerts for 2 minutes after they fired, across later ticks without alerts, or until the banner's new × is clicked. Ticks expire it. A `.task` on the banner expires it while Live is paused. Dismissing only hides the banner; the alert stays in Timeline.
